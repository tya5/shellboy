## Additional review limitation

Cross-review identified an inherited full-reserve case: a single frontend handler
can emit enough important updates to reach 512 while the UI remains stalled.
The corrected retry preserves FIFO and memory bounds, but delays polling frontend
priority actions until UI delivery resumes. The UI OS thread and reserved action
mailbox remain nonblocking. Fixing this fully needs bounded batch continuation
and reserved main-producer capacity together; neither a larger queue nor worker
admission alone proves responsiveness. Keep this explicitly documented rather
than claiming the ordinary pressure fixture validates every saturation case.
