# Shellboy v0.10.0

This draft tracks changes after [v0.9.0](https://github.com/tya5/shellboy/releases/tag/v0.9.0). It is not a release announcement.

## Breaking changes

One behaviour change that existing callers can observe, and one protocol-reply change; no command, flag or setting is removed.

- **Stop, retry and shell operations no longer check the caller ([#256](https://github.com/tya5/shellboy/issues/256)).** `run stop`, `run retry` and `shell write|eof|stop` used to refuse a model caller that did not own the Run (`invalid_state`: "Only a human or an owning Run may change this execution", and a direct-owner-only rule for retry). That check is deleted. Any caller, model or human, now succeeds on any Run or shell, so a script or model that relied on the refusal to protect another Run's work is no longer protected. Ownership is unchanged for notices (the owner still gets recovery and child-end notices), for stopping an owner stopping its descendants, and for the rule that a Run cannot wait synchronously on itself or an ancestor. The caller is kept in the operation receipt. Decision: user, 2026-11-07 (personal use; the Origin was never a security boundary).
- **An owner now answers an unknown command, unknown field or wrong argument type with `invalid_argument` ([#244](https://github.com/tya5/shellboy/issues/244) A1).** `details.reason` is `unknown_command`, `unknown_field` or `unknown_request_field`, `details.name` names it and `request_may_have_been_applied` is false; nothing is run. Before, the owner closed the connection and the client could not tell whether a mutation happened. `PROTOCOL_VERSION` stays 2. A client that treated a closed connection as "unsupported" must now read the typed error. Run the CLI and owner from the same release.

Not breaking but visible: `thread list` hides archived Threads by default (none exist before an upgrade); automatic compaction no longer repeats a failed summary stage within one Turn (see the table); embeddings are normalized to unit length before storage and comparison (see the table).

## Before upgrading

- Stop the owner, back up the complete data directory, update the owner and CLI together, and restart the owner.
- Conversation schema upgrades from 31 to 32 through migration `0032_thread_archive.sql` (one nullable `thread.archived_at` column and two partial list indexes; existing rows stay unarchived). Standalone RAG schema remains 4.
- Verify with `python3 scripts/check-release-upgrade.py --old OLD_BINARY --new NEW_BINARY --root EMPTY_TEMP_DIR --old-version 0.9.0 --start-schema 31 --expected-version 0.10.0 --expected-new-schema 32`.
- A newer `shellboy chat` follows with `events wait`, which an older owner does not know; update the owner and CLI together.
- A vector index built at a reduced dimension by an earlier version holds unnormalized vectors. Rebuild it (`index rebuild`) to get the new ranking; a 3,072-dimension index is already unit length and needs no rebuild.

## Unverified / pending

Synthetic compaction measurements do not establish real-provider latency, retention quality, or physical terminal behavior.
The #243 timings are one macOS run; Linux and Windows are not measured. No real-terminal check was made of the new TUI keys (Ctrl+A, Ctrl+G, `r`, Alt+U). The upgrade checker has not been run for 31 to 32 on this draft's tip.
Fixed test dates and two flawed tests were corrected ([#260](https://github.com/tya5/shellboy/issues/260) tracks other load-sensitive tests, which remain unexplained).
