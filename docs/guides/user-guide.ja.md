# User Guide

[ガイド一覧](README.md) · [設定・導入](configuration.md) · [画面操作](tui.md) · [English](user-guide.md)

Shellboyは端末で会話し、モデルにshell作業を依頼するアプリです。会話の保存先を管理するTUIを一つ起動し、外部の`shellboy` CLIもその起動済みアプリへ接続します。会話には接続先、モデルID、資格情報を設定します。既定はResponsesで、接続ごとにChat Completionsも選べます。ガイドは設定前でも `shellboy docs list` から閲覧でき、文書検索の `shellboy rag` も独立して使えます。

モデルへshell作業を任せる前に、[安全の考え方](#安全の考え方)を確認してください。

`usage get --group-by day|hour|thread` では、通常の `model_attempts` と分けて
要約（コンパクション）の使用量を表示し、両方を合わせたトークン合計も示します。
要約回数と map/reduce 要求数、提供元が報告した入力・キャッシュ・cache creation・
出力トークンを確認できます。期間の所属は最初の要約要求時刻で決まります。
未記録の値はゼロではなく不明のままです。要約記録も上限付きで走査し、cursorで
ページ送りします。これは使用量の記録で、費用の推定ではありません。


## UI の表示言語と診断

履歴 GC の実行後は、F1 または `/help` の DB / GC 欄で、段階、走査数、
予算による中断と再開始の回数、経過時間、最後の cursor 確定からの時間、
予算超過で保持した node 数を確認できます。これはメモリ上の観測値であり、
完了時刻を保証するものではありません。

TUI の既定の表示言語は英語です。起動前に設定ファイルで指定します。
起動中の TUI に反映するには再起動してください。

```toml
[ui]
language = "ja" # 日本語。英語は "en"
```

指定できる値は `en` と `ja` だけです。起動時は既存の設定 worker が言語を
読み込むまで英語で表示し、その後の起動段階、取消、失敗画面には読み込んだ
言語を使います。設定がまだ利用できない時点の端末接続エラーも英語です。

言語設定の対象は UI の見出し、説明、コマンド診断、アプリが生成した状態通知です。
会話本文、モデルやツールの文言、provider のエラー、パス、ID、コード、
コピーする原文、送信する添付は翻訳・書換えません。CLI の JSON の key/value、
protocol の状態、モデルに送る指示も変わりません。そのため provider や OS の
エラー原文が画面の言語と異なる場合があります。slash コマンド、ショートカット、
確認操作は両言語で同じです。言語を選ぶことが操作の実行許可になることはありません。

- **未知のコマンド / Unknown command**: `/help` を確認します。コマンド名は翻訳しません。
- **未受付 / Not accepted**: キューや受付条件の問題です。対象と保存済み入力の状態を
  確認してから再操作し、エラー文だけで受付・完了を判断しません。本文を保持したと
  通知された場合は、入力欄の本文を残しています。
- **再取得に失敗・以前の取得結果 / Refresh failed; previous captured result**:
  前回の観測値は現在の外部状態を保証しません。
  取得 UTC 時刻と最終要求時刻を確認し、表示された明示的な再取得・再確認を使います。
- **OSC52 のコピー要求**: 端末へコピー要求を送ったことと OS の clipboard 更新完了は別です。
  本文全体が12文字の場合、実際の表示は
  `OSC52: 本文全体のコピー要求を端末へ送りました（12文字・完了未確認）`、英語では
  `OSC52: completion unconfirmed for copying the complete body (12 characters). Request sent.` です。
  コピー範囲と原文は表示言語に依存しません。
- **強制終了 / Force quit**: 待機継続と強制終了は別の選択です。強制終了では未保存の
  データや未回収の所有プロセスが残る可能性があるため、再起動して中断作業を確認します。

一部の診断 field label と状態・revisit 表示には、共通 report の表記が残っています。
この typed UI projection は別途対応する範囲で、raw 値は変更しません。

外部観測 notice は記録された取得時点の事実を示します。表示言語のために描画中に
設定を読み直すこと、provider/OS を probe すること、確認を更新すること、要求を
自動で繰り返すことはありません。

## 会話と作業状態の読み方

| 通常画面で読む言葉 | 意味 | 詳細で対応する内部情報 |
|---|---|---|
| 会話 | 履歴・作業フォルダー・モデルをまとめた保存先 | Thread。親子の会話は履歴の系譜で、実行の所有関係とは別 |
| 依頼 | 送った本文。受付済みなら保存されている | message。accepted/held/appliedは回答の成否ではない |
| 処理中 | 準備、モデル応答、ツール実行や明示待機を進めている | Runは作業の寿命、Turnは次の回答までの処理単位。attemptは個々の通信 |
| 背景処理 | 回答後もshellや所有する子の処理が続いている | 完了したTurnとliveなRunは両立する。会話切替でも処理は継続 |
| 復旧待ち | 理由を保存し、再試行・新指示・停止の判断を待っている | Turnのrecovery_wait。Runはliveのまま、時間経過だけでは再開しない |

会話を選ぶ操作、現在の作業を止める操作、過去の結果を詳しく読む操作を区別します。
「受付済み」は保存の成功、「回答完了」はTurnの完了で、背景処理を含む作業全体の完了とは限りません。
IDやreceiptは調査の詳細情報です。普段は状態と理由を読み、必要なときに詳細から取り出せます。

復旧待ちでは保存済みの依頼を送り直す前に、理由と対象Runを確認します。
原因を直して同じ処理を試すにはF8のRun再試行か `shellboy run retry --run RUN_ID`、
やめるにはCtrl+Cか `shellboy run stop --run RUN_ID` を使います。
人間の新指示で同じ復旧Turnを再開することと、元の処理をretryすることは別です。
停止・再起動後の終端Runをretryで復活させることはできません。
保存済み内容と未確認の副作用を確認する手順は [復旧ガイド](recovery-and-storage.md) にあります。

次の区切りを待つ保存済みの入力は、入力欄の上と `/queue` に表示されます。CLIや別の会話から届いた入力も対象です。通常の送信は区切りまで待ちます。Ctrl+Enter（通常送信に設定済みなら除く）またはCtrl+X、Ctrl+Sの順で「すぐ渡す」を選べますが、応答の生成は中断しません。Escは画面を閉じる操作や履歴から入力欄へ戻る操作を優先し、履歴を選択していない通常の会話画面ではTurnだけを中断します。Ctrl+CはRunと、その背景の作業も停止します。未反映の入力は `/queue` で確認したIDだけを取り消せます。保存した入力は `/restore list` と `/restore draft ID` から復元でき、編集中の新しい入力は保持します。上限と確認操作は [TUI controls](tui.md) を参照してください。

## 1. 作業フォルダーで起動する

初めて使うときは、会話の前に次の順で設定します（PowerShellでも同じです）。

```sh
shellboy config init
# 表示されたconfig_pathを編集: API root、モデル、api_key_envの変数名を指定。
# keyの値はこの端末の環境変数に設定し、TOMLには書かない。
shellboy config check
shellboy
```

環境変数を設定する代わりに、起動中のownerにkeyを保存させることもできます。
`printf %s "$KEY" | shellboy credentials set --connection proxy`で、設定ファイルと同じ
フォルダーの`credentials.toml`に平文で保存します（値のある環境変数が優先されます）。
`shellboy connection test --connection proxy`は接続先にモデル一覧を問い合わせ、応答の
有無を示します。[keyの保存と接続確認](configuration.md#store-a-key-and-check-a-connection)を参照してください。

既存の設定ファイルは上書きしません。独自の場所なら全操作に同じ`--config PATH`を
指定してください。`check`はownerなしで使え、モデル一覧だけを要求し、会話の要求は
送りません。`base_url`は`https://proxy.example/v1`のようなAPI rootまでで、
`.../v1/responses`までは書きません。[初回設定](configuration.md#first-setup-without-an-owner)
にOS別の場所、資格情報とkeyなしのローカル接続の例があります。起動済みownerには
設定が自動反映されないため、設定やkeyの環境変数を直したらownerを起動し直します。


作業中の処理をまとめて見るにはTUIで`/status`、別の端末で`shellboy status`を使います。background shell、子Run、依頼の保留、モデル要求を保存済みIDから追跡できます。終了済みも見る場合は`/status all`又は`shellboy status --all`です。詳しくは[画面操作](tui.md#slash-commands)と[CLIの作業状態](cli-reference.md#common-syntax-and-connection)を参照してください。

まず[環境別の起動方法](configuration.md#starting-on-each-platform)で、端末・OS版binary・モデル用shellの組合せを選びます。[設定・導入](configuration.md) に従ってビルド・インストールと接続設定を行った後、ターミナルで次を実行します。例はBash/zsh用です。

```sh
command -v shellboy
shellboy --version
cd /path/to/project
shellboy
```

`/path/to/project`は実在する作業フォルダーへ置き換えます。短い名前がPATH上で見つからない場合は、インストール先のディレクトリを利用者のPATHへ追加するか、binaryを絶対パスで呼んでください。モデル用shellのCLI探索にはShellboyがPATHを自動設定します。接続先と資格情報の設定は [設定・導入](configuration.md) を参照してください。ソースcheckoutからのビルド手順は[開発環境](../development/setup.md)にもあります。

設定と保存先を明示する場合は次の形です。

```sh
shellboy --config /path/to/config.toml --data-dir /path/to/shellboy-data
```

引数なしの起動には対話端末が必要です。同じdata-dirではownerを二重起動できません。別ターミナルからのサブコマンドは起動済みownerを使い、ownerを自動起動しません。独立した環境が必要なら別のdata-dirを選びます。

`shellboy startup [--last N]`（既定5、最大20）で、ownerを起動・接続せずに最近の起動段階の所要時間を確認できます。`<data-dir>/logs/shellboy.log` と回転済みファイルを読み、合計16 MiB・64ファイルに制限します。出力は段階名、時刻、ミリ秒、migration/application version、合計時間、不完全な起動の注記に限定し、他のログ項目は出しません。ログはベストエフォートのため段階が欠けることがあり、欠落はゼロを意味しません。結果にも記録欠落の可能性を示します。データ保存先を解決できる前の設定エラーは記録できません。

起動中は設定・DB更新・前回中断した処理の整理など、現在の準備内容を表示します。 migration の印は構造更新の段数を示し、起動全体の進行割合ではありません。長い段では印が変わらず、残り時間の推測は表示しません。幅が足りないときは段数だけを表示します。会話入力は起動完了後に行います。Esc / Ctrl+C / Ctrl+Qで終了を要求すると、開始済みの初期化と保存処理を安全な境界まで進めてから閉じます。DB更新を巻き戻したり、直ちにlockを解放したりする操作ではありません。起動に失敗した場合は表示された理由を確認し、EnterかEscで閉じます。

新しいルートThreadのcwdは起動フォルダーです。保存済みThreadを開くと、そのThreadのcwdを使い、今回の起動フォルダーで上書きしません。`/cwd`、又はF8の「会話 | 詳細」で確認できます。

### 会話の形式を選ぶ

接続の既定は`api = "responses"`です。Chat形式のOpenAI互換の入口では
`api = "chat_completions"`を指定してownerを起動し直します。[形式のガイド](configuration.md#conversation-api-dialect)
に**未検証**のGemini例と使えない機能を記載しています。Responsesの推論項目・暗号化
推論はChatへ持ち回さず、vendorの`reasoning_content`も使いません。確認したのは
合成SSEとloopback mockだけで、実プロバイダはすべて未検証です。`usage get`とF6の
キャッシュ使用量は返った値だけで、不明を0にはしません。F6と`usage get`は送った要求の入力のバイト数（UTF-8）を種類別に実測して並べますが、トークンへは換算しません。一覧の確認だけでは
キャッシュの実効性は分かりません。Anthropicの互換の入口はキャッシュが使えないため
対象外です。長い会話には本来のAPIに対応するproxyを使ってください。

## 2. 最初の依頼を送る

会話のない新しいThreadでは、Shellboyのロゴと、その右にバージョン・モデル・作業場所・設定ファイル・データディレクトリを表示します。端末が狭いか低いとき、または必須設定が足りないときは、従来の縦の案内か設定の説明を表示します。

下書き欄に依頼を入力し、既定ではEnterで送信します。Ctrl+Jは常に改行できます。Shift+Enterは端末がキーボード拡張に対応している場合のみ利用でき、未対応の端末ではCtrl+Jを使ってください。例えば「このフォルダーのREADMEを読み、構成と次の作業候補を説明してください」と依頼できます。モデルにはshellツールがあるので、実ファイルを変更する依頼はその作業フォルダーで実行され得ます。

初回送信でThreadと依頼が保存されます。「受付済み」はDB保存を表し、回答・shell・Runの完了とは別です。受付後の準備や通信に失敗した場合も、保存済み依頼は残ります。失敗内容に従い対処してから明示的にretryします。[復旧・保存](recovery-and-storage.md)を参照してください。

受付完了までは本文・添付を表示し続けます。この間の編集は送信時点のsnapshotには反映されず、遅れて届く受付結果も編集後の下書きを消しません。キュー満杯や保存失敗の表示が出た場合は、本文を確認してから再操作します。長文貼付けは自動送信されず、[折りたたみ表示](tui.md#pasting-long-text)から確認できます。

## 3. 会話を切り替える

- `/new`またはCtrl+Nで新しい下書きを作ります。最初の送信前はまだ保存済みThreadではありません。
- `/threads`で1行ずつの一覧を開き、上下キーとEnterで選びます。Ctrl+TはこのUI内の直前の一覧／Watchを開きます（起動時は一覧、以前の子孫範囲や絞り込みは引き継ぎません）。左右キーで親子を開閉・移動し、文字入力で絞り込みます。選択した項目の詳細と短い会話抜粋は下部、完全値はF1から確認できます。
- 一覧内のTabでWatchへ切り替えます。`/threads active`で直接開き、`/threads descendants`またはAlt+Dで現在の会話の子孫を監視できます。Enterで会話へ移動、Ctrl+S/Alt+RでRun停止／復旧待ちの再試行を確認し、Alt+Oで保存出力を読みます。[Watchの詳細](tui.md#watch-work-and-descendants)も参照してください。
- IDが分かる場合は`/switch THREAD_ID`で移動できます。

一覧を開いている間も、保存済みタイトル・状態・追加・削除が自動で反映され、選択と親子の開閉状態を保ちます。新しい行が現在の閲覧位置より上に入る場合は、上キーで移動できます。「再確認中」は、再取得後に以前の選択先を確認している印です。Ctrl+Rで明示的に再取得でき、変更通知を取りこぼした場合は理由を表示して再同期します。

Threadごとに下書きと閲覧位置を持ちます。切替は実行停止を意味しません。前のThreadでshellや子Runが動いていれば処理を続けます。回答後も背景処理が残ると、Turnは完了していてもRunは継続する場合があります。Thread・Run・Turnの違いは[委譲](delegation.md)を参照してください。

### 会話を読む

自分の発言は横幅いっぱいの帯で区切り、幅に余裕があるときは保存時刻を右端に
表示します。親・モデル自身・別のモデル・Revisitから届いた入力は、出どころの
印で区別します。画面上部の固定行は会話本文とは別の表示で、左にタイトルと状態、
右に接続先・モデル・作業場所を示します。長いパスは先頭を省き、元の値は詳細で
確認できます。

自動で表示するタイトルが「名称未設定（元本文の取得範囲外）」の場合、先頭の
依頼を確定するための原文がヘッダーの取得上限を超えています。履歴が空という
意味ではありません。履歴を確認するか、会話にタイトルを設定してください。
この表示で保存済みのタイトルを書き換えることはありません。

shellの呼び出しは、コマンドと判明している結果・所要時間を1行にまとめます。
IDや応答内の呼び出し番号は詳細で確認します。成功した出力は閉じた状態から始まり、
失敗した場合は保存出力の末尾を短く開きます。保持されているstderrも対象です。
行を開くと上限付きの抜粋を取得し、長い出力を会話画面へ全部読み込みません。
省略した抜粋も実際の保持出力の末尾を使います。文字境界・文字コードの状態が
不確かな場合はその旨を表示するので、必要に応じて原文を確認してください。
表示の開閉でコマンドを実行・再試行・停止することはありません。

| 場所 | キー | 操作 |
|---|---|---|
| slash候補のない入力欄 | Tab | 表示中の履歴項目を選ぶ |
| 履歴を選択中 | ↑ / ↓ | 発言やshellの行を移動する |
| 履歴を選択中 | Enter / Space | 選択項目をその場で開閉する |
| 履歴を選択中 | `o` / `c` | 原文を開く／元の内容をコピーする |
| 履歴を選択中 | Esc / Tab | 入力欄へ戻る |
| 会話画面 | F6 / F7 | 同じ選択項目の詳細／リンクを開く |
| 入力欄 | Shift+Tab | 入力欄の上にある「抱えている作業」を選ぶ |
| 入力欄 | Alt+W | 「抱えている作業」の中身を開閉する（見出しのクリックでも可） |
| 作業を選択中 | ↑ / ↓; Space | 作業を選ぶ／選択したshellの出力を開閉する |
| 作業を選択中 | F6; `o`; Esc | 詳細フォーム／子の会話／入力欄へ戻る |

マウス取得が有効なとき、展開可能なshell／結果行や通知グループ行はクリックで開閉できます。
通常のユーザー／モデル発言行や応答受信行は、クリックしても選択・開閉されません。
ほかの履歴項目はTab／矢印キーで選択し、EnterまたはSpaceで開閉してください。
空の入力欄での↑は送信済み文章の呼び戻しです。詳細を開いても新しい依頼は送りません。
コピーや原文の対象は保存した元の内容なので、画面上の抜粋より長い場合があります。
F6の原文ページでも、そのページのコピー操作を使えます。

URLや`file://`付きのファイル・フォルダのパスを開くのは、Shellboyではなく端末の機能です。
weztermではShift+クリックを使います。Shellboyがマウスを受け取るため、Shiftで端末へ
操作を渡します。既定の規則で`file://`を開けます。付いていない素のパスには
`hyperlink_rules`の規則を足してください（[短い設定例](tui.md#open-urls-and-file-paths-with-your-terminal)）。
iTerm2ではCmd+クリックを使います。キーの割り当ては端末設定によって異なり、
何をどのアプリで開くかは端末とOSが決めます。Shellboyはパスの実在確認やアプリの起動をしません。

出力の抜粋と原文ページには、読込み成功時に一度だけ記録したUTCの読取時刻を
表示します。toolの行を閉じて開き直すと、実行し直さずに保存出力を再読します。
F6の原文ページではOで選択元を再読、Nで次のページ、Pで先頭のページを読みます。
表示中の履歴項目のF6/F7では、変化する事実やリンクを保存済みの変更に合わせて
自動更新します。通知は500msまとめ、空いているローカル環境では1秒以内を目安に
しますが、API・通信・混雑中のDBの鮮度を保証するものではありません。更新に失敗
した場合は、保持した情報が古い可能性や取得不能であることを表示します。

F2は自動再描画を止め、固定モードに入ったUTC時刻を記録します。F2/Escで更新を
再開します。固定中のCtrl+Lは、現在UIに届いている内容を一度だけ再描画する操作で、
DBの再取得や固定開始時刻の更新は行いません。固定開始時刻と、各抜粋の読取時刻は
別の意味です。

通常の観測事項は発言の区画の最後に薄い字でまとめ、失敗や復旧判断が必要な情報は
目立たせます。下部には現在の動き・反映待ちの入力・具体的な通知と短いヘルプ案内を
表示します。成功した操作の通知は次の入力で消え、失敗は次の意図的な操作まで残ります。
回答済みでも背景の作業が残る場合があるので、`/status`や既存のF8のRun・shell詳細で
確認してください。

設定ファイルの`palette`を`dark`（既定）または`light`にして配色を選び、TUIを再起動します。

```toml
[ui]
language = "ja" # "en"（既定）または "ja"
palette = "dark"
```

`language` の変更後はTUIを再起動してください。段階Aでは強制終了確認と
端末幅の診断を切り替え、他の画面は後続の作業で移行します。利用者やモデルの
本文、CLI出力、保存データは翻訳しません。TUIは起動時に曖昧幅を測定し、F1の
ヘルプに結果を表示します。端末から一貫した応答を得られない場合は不明として
2列を確保します。幅の設定やlocaleによる推測はありません。

`NO_COLOR`では印と空行で区切り、256色・truecolorを通知しない
端末では反転や区切り線を使います。色がなくても入力元や選択項目を区別できます。

過去の履歴を読む・履歴項目を選ぶ操作で末尾への追従を止めます。新着があるときは
その印を表示し、Ctrl+Endで末尾追従へ戻ります。背景の更新だけで追従を止めたり、
表示済みの応答を消したりはしません。フォークや依頼編集、検索filterと出典・直接の
関係の確認は[履歴と検索](history-and-search.md)で説明します。

F8は「この会話で」「よく使う」「その他の操作」に分かれ、見出しは選択されません。
操作の意味・人向け名・CLI名・関連するslashで絞り込めます。[変更]は保存データの変更、
[制御]は処理の開始や制御です。フォームには作用、IDの種類、初期値の出所、探し方を表示し、
F1で説明を確認できます。Enterは操作に応じて表示・実行・送信になります。
保存状態が変わっても編集中の値は保持します。owner操作に加え、docs/config/RAG/execの
独立クライアントも選べ、費用が発生しうる処理は明示確認してから実行します。
結果は項目と値で表示します。

ホイールは最前面の描画済みポップアップを動かし、背景の会話は動かしません。
ポップアップの外側、スクロールの端、F2の端末選択中は動きません。
詳細なキーとコピー範囲は[画面操作](tui.md#read-source-text-and-links-from-details)を参照してください。
会話ブラウザーの一覧・Watchと、F8の操作フォームは別の機能です。

### 保存済み使用量の確認

- F8の「使用量 | 合計」で確認でき、必要なら子会話も含められます。
  CLIは `shellboy usage get --thread THREAD_ID --include-children` です。
  この会話だけなら最後のflagを外します。
- 保存済み記録の合計で、請求額や実働時間ではありません。時間の種類は
  重なり、未報告・未記録の使用量は0ではなく不明として表示します。
- 重いと感じたら `<data_dir>/logs/shellboy.log` の
  `event=usage_totals_slow` を確認します。100ms以上の集計だけが出ます。
  更新やsnapshotの詳しい挙動は[画面操作](tui.md#saved-usage-details)にあります。

## 4. 接続・モデルを変える

`/model`だけで現在値を表示します。`/models`で現在の接続先のモデル一覧を取得できます。文字入力で絞込み、上下で選択、Enterで現在の会話のモデルを変更します。Escは閉じるだけです。別の接続先を見る場合は `/models CONNECTION` を使います。直接指定する場合は以下です。

```text
/model CONNECTION MODEL_ID
/effort medium
/cwd /path/to/other-project
```

`CONNECTION`と`MODEL_ID`は実際の設定値へ置き換えます。一覧は接続先から取得し、モデルや対応effortをShellboyが内蔵しているわけではありません。接続先がembedding等も列挙した場合は一覧に含まれ、会話APIで使える保証ではありません。取得未対応の接続先では `/model CONNECTION MODEL_ID` で直接指定できます。`/effort none`はeffort指定を解除し、モデルへ`none`を必ず送る指示ではありません。モデル変更でも既存effortは保持するので、必要なら明示的に変更・解除します。

変更は以後の要求に反映され、既に送信済みの通信を書き換えません。接続・モデル変更では推論の送信epochも変わり、元モデルへ戻しても古いopaque reasoningを自動復活しません。会話原文は残ります。

### 出力上限

接続の任意の正整数`max_tokens`は、Responsesでは`max_output_tokens`、Chat
Completionsでは`max_completion_tokens`、Messagesでは`max_tokens`へ送ります。
未設定なら前二者は上限フィールドを省略し、Messagesは従来の32768を維持します。
コンテキスト上限とは別です。接続先とモデルが対応する値だけを指定してください。
Shellboyは上限カタログを問い合わせません。

プロバイダーが明示した出力上限終了は成功ではなく`output_limit`と設定案内で表示します。
部分出力は復旧・監査用で、完成した回答とは扱いません。他の未完了理由や通信中断は
再分類しません。ResponsesとChatはJSONとstreamに対応し、Messagesは従来どおり
streamのみです。`max_tokens`指定時に`extra_body`へ同じAPI固有キーを重ねると、
暗黙上書きせず拒否します。[設定ガイド](configuration.md)も参照してください。

## 5. 子へ委譲する

「サブエージェントを使って」と言うだけで、モデルがShellboyの子Thread操作を正確に理解する保証はありません。ガイドは実行ファイルに同梱されています。モデルには短い入口の案内が渡り、必要なときに自分でガイドを読みます。全文が毎回の指示に展開されるわけではなく、checkoutやリポジトリのパスも不要です。確実に手順を読ませたいときはガイドIDを書きます。

```text
まず shellboy docs get --id shellboy/agent-guide と
shellboy docs get --id shellboy/delegation をshellで読んでください。
その手順で所有する子Threadを作り、調査だけを委譲してください。
子への依頼は `message send --expect-reply` を使い、`reply_received` で待ち、返信状態と原文を確認して結果をまとめてください。
```

親子の停止範囲、途中報告、recovery待ちの判断は[委譲ガイド](delegation.md)にあります。

Threadの`AGENTS.md`参照先は作業上の指示です。新しいルートThreadの既定はcwdの`AGENTS.md`で、新Turnの準備で読み、同じTurnのretryは保存済みsnapshotを使います。Agent Guideは操作の説明書、リポジトリ直下の`AGENTS.md`はそのリポジトリの作業指示で、用途が異なります。

### TUIを使わずに話す

`shellboy chat` は、起動中のownerが持つ会話へ行単位で話しかける簡易クライアントです。
先に `shellboy serve --data-dir DIR`（またはTUI）でownerを起動し、
`shellboy --data-dir DIR chat` を実行します（既存の会話は `--thread THREAD`）。
メッセージを入力してEnterで送信し、行末の `\` で次の行へ続けます。進行は
`[turn] running` や `[tool] ...` の1行表示で、完了後に最終メッセージを
プレーンテキストで表示します（Markdownは整形しません）。Ctrl+CでTUIと同じく
現在のRunを停止し、2回目で終了します。`/exit` またはCtrl+Dは、作業を止めずに抜けます。
端末から打った入力は人の送信として、パイプ入力は `external_cli` として記録されますが、
どちらも打った人の証明ではありません。終了コードと `--json` の行形式は
[CLIリファレンス](cli-reference.md#interactive-chat-client-242)を参照してください。

## 6. 中断・終了する

Ctrl+Cは現在会話のRunと所有する背景処理の停止です。Escは開いた画面を閉じ、それ以外では現在のTurnだけを中断します。Ctrl+Bは現在のforeground shellを背景へ移す操作です。背景化では対象shellを継続し、同じgroupに未実行後続callがあれば取消しにします。画面を切り替える操作とは区別してください。 背景化後は対象shellと後続の扱いを画面へ通知し、モデルにも対応する結果を渡します。後続がない場合は存在しない取消しを表示しません。中断は保存済み状態に従って停止処理中から中断済みへ変わり、背景化や完了と区別されます。

処理の完了を観測するwaitと、対象を中断する操作は別です。F8の待機フォームから開始した観測だけをやめるなら、結果画面で小文字w、又は `/cancel-wait` を使います。対象Run/shellは止まりません。フォーム内ではEnterが実行、複数行の本文入力はCtrl+J、候補値の置換はCtrl+Uです。

終了はCtrl+Qまたは`/quit`です。保存と所有する処理の停止・回収を待ちます。猶予を超えるとW/Enterで待機継続、Fで強制終了の確認へ進み、さらにYで確定します。強制終了は未保存・未回収の可能性を伴います。詳細は[復旧・保存](recovery-and-storage.md)にあります。

次に使う機能は[添付](attachments.md)、[履歴と検索](history-and-search.md)、[全CLI参照](cli-reference.md)から確認できます。

削除前にF8の「会話 | 削除影響」で、動作中Run・子孫・共有や出典・添付参照を確認できます。照会だけでは削除せず、容量の回収見積もりは未対応です。受付や圧縮結果を見失った場合はF8の「操作 | 受付結果」で対象operationを照会し、後続状態も確認します。詳しくは[復旧・保存](recovery-and-storage.md)を参照してください。

### 推定に頼らない復旧

復旧待ちではF8のRun/Turn詳細で失敗と再試行の記録を確認します。
添付の形式が拒否された場合、`/attachments` で対象を確認し、`/detach ATTACHMENT_ID` で送信対象から外してから `/retry` できます。ファイル自体は削除しません。外部ファイルを一時的に移動する代替策と注意点は[復旧・保存](recovery-and-storage.md)を参照してください。
`/compact-max` は要約APIを使わず保護外を縮小します。再送は別の
`/retry` で行い、追加料金が発生することがあります。省いた本文は
`/restore` で戻せます。token推定と75kの閾値はなくなりました。
最後に成功したときの実測使用量と時刻は `shellboy thread get` で確認できます。

大切な範囲を変更する前に `shellboy compact --dry-run --thread THREAD` で見込みを確認できます。
これは開発版の機能で、summary・spill・trim・omit・maximal にも指定できます。
モデル要求と経路変更は行いません。予測された失敗と取得上限を確認してください。
要約文の長さは未確定で、会話が変わった後の編集を許可するものでもありません。
詳しい上限は CLI reference を参照してください。

## 保存とリソース

会話・回答・推論・要約はデータディレクトリに保存され、自動では期限切れ削除しません。
shellの生出力と管理されたクリップボード画像は別に扱います。

- 終了したshellの生出力：既定7日 / 合計1GiB（`retention.tool_raw_days`、`tool_raw_bytes`）。
- 管理画像：既定7日 / 合計256MiB（`retention.clipboard_days`、`clipboard_bytes`）。

動作中のshell、pin、選択中の画像、保存済み下書きなどは回収から保護されます。
回収後も履歴の参照と読めない理由は残りますが、生の内容は復元できません。
管理PNGは `<data_dir>/managed/clipboard/` にありますが、絶対 `path` は恒久保存先ではありません。GCは外部の原本を消しません。

ownerの動作中にGCが自動で動き、処理後およそ1分で次の回収を始めます。
生出力・履歴のDB処理は最大128件単位で進み、1分に128件という上限ではありません。
回収で空いたSQLiteのページは再利用します。自動VACUUMでDBファイルを縮めることはありません。縮めたいときは、Shellboyを終了してから `shellboy storage vacuum --dry-run` で縮む量と必要な空き容量を確認し、`shellboy storage vacuum` を実行します（明示したときだけ動きます）。
容量を減らすには `shellboy storage status` → `shellboy storage collect` で確認・回収し、
不要な会話を `shellboy thread delete-preview --thread THREAD_ID` で確かめてから
`shellboy thread delete --thread THREAD_ID` で消します。回収は保護・共有を尊重し、
previewは読取りだけで回収容量を見積もりません。詳しくは[復旧・保存](recovery-and-storage.md)を参照してください。

RAMの `[cache]` の上限は既定で `body_bytes` 32MiB、`layout_bytes` 16MiB、
`history_bytes` 32MiB、`attachment_base64_bytes` 64MiBです。
設定を小さくしてownerを再起動できます。`0` は保持cacheを無効にしますが、
処理中の作業メモリや保存済み履歴はなくさず、プロセス全体のメモリ上限でもありません。
`shellboy status --memory` でownerのcache内訳とOSのプロセスメモリをその場で確認できます。
不明値は0でなくnullです。cacheの値をfootprint/RSSに足してはいけません。
設定は[Configuration](configuration.md#all-sections-and-defaults)、観測の詳細は[CLI参照](cli-reference.md)を参照してください。

## 安全の考え方

ツール行の説明はモデルが書いたもので、コマンドとの一致は検証されません。
実際に動いたコマンドは、行を選ぶか F6 で確かめてください。

**前提。** モデルの道具は汎用のshellだけです。コマンドは既定ではownerと同じ
OSユーザーの権限と引き継いだ環境で動き、Shellboyはコマンドごとの確認を挟みません。
Shellboyはファイル・ネットワークのsandboxやコマンド禁止一覧を持ちません。
cwdは開始場所であって境界ではなく、会話やworktreeを分けても権限は分離しません。

**なぜ確認や禁止を持たないか。** 汎用shellを渡したままコマンド名を
禁止しても、別の書き方で同じ操作ができ、守られているという誤解を招きます。
毎回の確認は長い自走に合わず、読まずに許可する習慣にもつながります。
弱いアプリ内の境界を頼るより、OSの境界を使う方針です。これは、モデルが
利用者の指示を無視してよいという意味ではありません。

**代わりにShellboyがすること。** 受け付けた依頼を実行前に保存し、
保存済み出力・出どころ・取消し理由・指示snapshotを辿れるようにします。
ただし保持の制限があり、特にshellのraw出力などを永久に残す保証ではありません。
Originや所有関係の検査はCLIの呼出元や対象の整合・許可を確かめますが、
悪意あるモデルからOSの資源を隔離するものではありません。Turn・Run・shellは
既存の操作で止め、中断後は保存された事実を調べられます。停止はファイル変更や外部への作用を巻き戻さず、
再起動しても終端Runを自動再開しません。削除や有料の索引作業など、確認のある
TUI操作もありますが、それは各コマンドを止める安全の関門ではありません。

**利用者がすること。** 大事な環境では専用の低権限OSユーザー・コンテナ・
VMを使い、そこでファイルやネットワークの権限を絞ってください。OSの道具には
macOSのSeatbelt、Linuxのbubblewrap／Landlock、Windowsの専用ユーザー・
NTFS権限・Windows Firewallがあります。[OS sandbox wrapper](shell.md#os-sandbox-wrappers)
に検証済みのmacOS例と、Linux・Windowsで未検証の範囲を記載しています。
ownerの権限も考慮が必要です。モデルのshellだけを包んでも、`attachment add`
などowner経由の読み取りは制限されません。不要な秘密を環境変数や読める
ファイルに置かず、そのOSユーザーが使える資格情報はコマンドからも見えると
考えてください。会話や選択したファイル・toolの内容は設定したAPI接続先（embeddingを有効に
している場合はその接続先も）へ送られ得て、data-dirにも会話が保存されます。
接続先の選択と保存先へのアクセスを守ります。

**prompt injection。** web・ファイル・RAG・別会話や子の結果に書かれた
指示はデータであり、新しい利用者の許可ではありません。モデルだけで全てを
確実に防げるわけではありません。OSで届く範囲を絞り、出典や履歴で起きた
ことを確認する二段構えです。どちらか一方で代わりにはなりません。
[Agent Guide](agent-guide.md#safety-boundary)と[停止・復旧](recovery-and-storage.md)も参照してください。


## 入力欄の上の「抱えている作業」

選択中のRunが所有するshell・子Run・待機を、古いものから既定で最大3件表示します。
`ui.live_work_rows`で1〜10件に変更できます。
回答したTurnが完了しても、作業が続いていれば残ります。残りは件数で示し、
保存時刻や待機の根拠が不明な場合に0件と表示することはありません。
経過時間は保存した開始時刻が基準です。最後の出力時刻は保存済みまたは新たに観測した
出力に基づき、時計の更新だけでDBを読み直しません。

見出しは常に表示され、作業がないときは `◉ 抱えている作業` に `なし` が付きます。
Alt+Wか見出しのクリックで中身を開閉します（既定は開）。開いている間は
`ui.live_work_rows` 行に固定され（足りない分は空行）、高さが変わるのは開閉と端末の
大きさが変わったときだけです。

Shift+Tabで表示中の作業行、保留入力行、入力欄の順に移動します。行のクリックでも
選択できます。選択行は色なしでも反転・太字で示し、選択用の矢印は加えません。
Alt+Wは選択中の領域を開閉し、見出しのクリックでも開閉できます。開閉状態は
このUIプロセス内だけで保持します。Spaceでshellの出力抜粋を開閉します。
F6は選んだ作業の詳細フォーム、`o`は子の会話、Escは入力欄へ戻る操作です。
出力を開いてもコマンドは実行・停止しません。開いた出力は最大毎秒2回更新し、
追いつけない場合は末尾へ移ったことや復号の不確実さを表示します。
閉じた画面・別の画面に覆われた場合・会話切替では抜粋の購読を止めます。
F2の画面固定は従来どおりです。表示上限を超える作業や詳しい保存情報は`/status`やF8で
確認できます。

### 返信待ち

表示中のスレッドの`◉ 返信待ち`区画には、人への質問と他スレッドへの返信依頼がまとめて表示されます。既存の人／モデル印で区別し、質問文と経過時間を確認できます。`ui.awaiting_human_rows`は固定表示行数（1〜10、既定1）です。Shift+Tabは作業中、保留中の入力、返信待ち、入力欄の順に移動し、空の区画は飛ばします。Alt+Wで最後に選んだ区画を折りたためます。反映済みの項目でEnterを押すと返信入力になり、Escでは下書きを保持します。`/replies`では一覧の続きも確認できます。

### 保留中の入力

作業領域と入力欄の間に`◉ 保留中の入力`を表示します。空でも`なし`を付けて残り、
点滅しません。本文は`ui.held_input_rows`で1〜10行（既定3行）に設定でき、
足りない分は空行です。小さい画面では表示を減らし、保存済み一覧の取得上限を
超えた分も含めて省略件数を示します。抜粋と保存済みの状態・理由を表示し、
狭いときは理由を短くする前に時刻を省きます。

印は人の入力が`›`、外部CLIまたは送信元不明が`⇥`、モデルからの入力が`↳`、
完了時に届ける予約が`↻`です。完了時の印は保存済みの予約・配信経緯に基づき、
元の`deliver`指定だけでは判断しません。復旧待ちへ移った入力も推測で予約扱い
しません。送信受付中の下書きは全文を複製せず、長さを制限した抜粋を表示します。

保留行のSpaceは保存済み原文、F6またはEnterは状態を非同期で取得します。
`d`は選んだ保存済みID、`a`はこの領域に実際に表示した保存済みIDの取消確認です。
保存前の送信受付行には、原文取得・取消対象の保存済みIDはまだありません。
`/queue`の一覧・原文・状態・取消、`/replies`、保存した下書きの復元は残ります。

### 会話の行の印

`▸` は回答、`▹` は呼出し、`⏵` は実行中、`◌` は観測不明、
`✓`・`✗`・`⊘` は終了結果、`⁂` は通知、`⬦` は要約、`>` は退避です。
背景の shell は「背景」と表示し、分かる場合は背景へ移した理由も出します。
経過時間は保存された shell の開始時刻を基準にします。
通知を Tab・矢印キーで選び、Enter で元の tool 行や子の会話へ移れます。
元の行が表示範囲外なら、その旨を表示します。F6 で保存済みの参照を確認できます。
種類の境目の空行は選択対象ではなく、続く tool の行は詰めたままです。

### providerのフィルターで未完了になった応答

応答が未完了のとき、保存済みの `incomplete_details.reason` と、providerが
返したフィルターの判定を有界な長さで表示します。`protected_material_code`
などの名前と値は翻訳・解釈しません。返ってこなかった項目は「不明」です。
カテゴリ名だけで判定の原因は断定しません。詳細、`turn get`、`run get` で
保存された事実を確認できます。表示上限による省略は明示され、保存原文は
既存の原文取得から確認できます。

理由が `content_filter` なら、明示的な再試行（毎回同じ判定とは限りません）、
指示を言い換えて再開、関連するツール出力や添付を外す、という手があります。
添付を外す操作は `/detach` です。既存ファイルの複写が目的なら、モデルに
本文を出力させず、shellの `cp` や `curl` で複写する方法もあります。成功を
保証したり、新しい副作用を許可したりする案内ではありません。未完了の終端
応答を受信済みなら自動再試行は行いません。通信中断の再試行方針は変更せず、
フィルターや再試行の新しい設定項目も追加しません。

`/replies` で現在の会話の反映済み依頼を選び、返信先を確認して通常の送信キーで本文だけを返信できます。Escで返信モードを抜けても下書きは保持します。元の行には返事待ち・返事済み・返事なし・取消・相手削除の状態、返信行には元の依頼の抜粋を表示します。既存の送信者記号は変えません。[返信の操作](tui.md#replying-to-a-request)も参照してください。

### 端末の文字残りへの対処

ヘルプを閉じた後やスクロール中に文字が残る場合は、`[ui]` に
`clean_redraw = true` を設定し、Shellboy を再起動してください。
オーバーレイを閉じると画面全体を消去して再描画し、履歴の表示位置が動くと
左右端を含む移動行を消去して書き直します。追加の端末出力で操作が重くなる場合は
`false` に戻してください。ログのように差分が少ない履歴では出力量が増えるため、
既定値は `false`（無効）です。
どちらの値でも Ctrl+L による手動の
全再描画は使えます。`shellboy config check` で真偽値の設定を検証できます。

合成端末でのテストは、消去命令の出力とモデル上のセルを検証するものです。
フォントの実ピクセルを検証するものではなく、Windows 実機は未検証です。
お使いの端末とフォントで改善するかを確認し、結果をお知らせください。
