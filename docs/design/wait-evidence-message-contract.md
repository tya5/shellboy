# Wait, failure evidence, and message contracts (#421 proposal)

## Non-goals

- No capability removal, compatibility aliases for approved pre-1.0 renames, new RPC mechanism, command, table, persistent state, dependency, event feed, or retry loop.
- No new cursor format or checkpoint store, polling fallback, invented budget, changed timeout, receipt rewrite, or deployment/pin change. Do not use a transport failure or missing receipt to authorize replay.
- No change to address defaults, access checks, reply duties, scheduling, accepted sender attribution (#420), or persisted routing and recovery. No rework of #416 record pages.
- This is a design, not approval to implement. Source locations refer to Core at `de1603a6e50346f69e483e44b715a7ef213e8ae4`. The order reflects failure cost, not measured frequency: a mistaken stop or duplicate mutation has more consequences than needing to look up a flag.

## 3. Wait and output following

Use one rule: a **cursor belongs to its issuer and target**, and a **wait reports what can be observed**, not what succeeded. `wait` has ANY semantics; the nonempty `matched` list says which predicates held. If none matched, interpret `status` (`timeout`, `interrupted`, `recovery_wait`, `unavailable`) and `snapshot`; first distinguish CLI admission exhaustion from an owner observation. None instructs a stop or a retry. A terminal state can be unsuccessful. Check the exact IDs, not the latest work on the Thread.

## 5. Errors, hints, and evidence

The **caller decides from typed evidence**, not `message`, `hint`, prose in `result.reason`, an exit code, or an API error code alone. The operation receipt is evidence about the original operation; it is not a second execution and need not describe downstream completion.

## 2. Message addressing, body, and acceptance

Use one presentation order in help and examples: **body input, explicit address or prior request, delivery timing if supported, reply duty**. Keep verb-specific omission behavior, but never rely on it in the first example. Replacing `send` with `ask` without specifying a destination can change both the destination and who owes a response. This is a risk identified by the audit, not a claim about a measured incident rate.
