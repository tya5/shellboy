# Protocol 16 (#316, #344, #345, #348, #352, #371)

Thread artifact metadata uses `artifact.add`, `artifact.update`, `artifact.list`,
`artifact.get`, and `artifact.remove`. The owner stores opaque URI, title, and
optional MIME strings; updates append versions. List pages use descending update
time and ascending ID, and `artifact.get` can read an exact version or page
through version history. See [Thread artifacts](../thread-artifacts.md) for request
limits, cursor scope, and lifecycle behavior.

`history.export` is a read-only owner observation with `{thread_id, cursor?, limit?}`. Its `items` enumerate retained current-path nodes and their recursively replaced sources once in saved insertion order. `payload_json` is the original stored JSON text, not a reserialized object; it can contain encrypted reasoning. Retained rows whose bodies were collected return tombstones with path and graph metadata. Relations carry replacement group IDs, ordered source ordinals and explicit internal/external/missing node references; entirely removed records cannot be exported. The cursor is scoped to the Thread and owner instance. Each page reads live saved state and returns `change_position` from the owner's existing Thread change clock. A change does not invalidate the cursor. The clock is a hint, not a snapshot or GC fence. Pages return fewer records as needed to fit the frame; if the next single record cannot fit, `input_limit` identifies its `node_id`.

`thread.import {document}` accepts one verified version-1 Thread export as JSONL text. The request, including JSON escaping and the IPC envelope, must fit the existing frame bound. The owner revalidates the document and returns `{thread_id}` after one receipt-backed writer transaction. No Run or Turn is restored.

The `service.add`, `service.list`, `service.start`, `service.stop`, and `service.remove` operations manage Thread-owned shell services independently of Runs. Unexpected exit disables the service and sends one ordinary notice to its Thread. Thread-owned output rotates, reporting `output_expired` for an evicted cursor and retained offsets on a fresh read. See [Thread-owned shell definitions](../thread-owned-shells.md).

`wait` and `events.wait` share a separate pool of 32 permits. Plain owner `status` exposes `ipc_admission` with the connection cap and per-class limits and refusal totals. `wait` results expose `admission_wait_ms` and `admission_refusals`; only CLI `wait` retries definite, unapplied admission refusals, retaining the original cursor and deadline. See [IPC admission](../protocol.md#ipc-admission).

`thread.list` accepts optional `thread_ids`, an array of up to 200 distinct, nonempty Thread IDs. It returns the usual `ThreadSummary` items for those IDs, including archived Threads, in unspecified order and without a next cursor. Unknown and deleted Threads are omitted; an empty array returns no items. Omit the field to keep the ordinary list behavior. The ID lookup does not use `limit` to truncate results and cannot be combined with a cursor, nondefault order, or list filters.
