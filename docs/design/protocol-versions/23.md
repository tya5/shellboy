# Protocol 23 (#399, #400)

- `message.send.max_model_requests`: optional positive 32-bit request ceiling
  for a new Run. An active Run makes the send fail with `invalid_state` and
  `details.reason=model_request_ceiling_requires_new_run`.
- `run.get.model_requests` reports `{ceiling,used}` for limited Runs.
  `run.get.stop_reason` is `{kind:"model_request_ceiling_reached",requests_used:N}`
  when the next request is refused by the ceiling. Both fields are optional.
- Schedule command text can use the existing message operation. No schedule
  wire change. Persistent counters use migration `0065_run_request_ceiling`.

# Model recovery next actions (#400)

Saved Turn recovery errors distinguish `model_auth`, `model_request_rejected`,
and `model_request_failed`; provider text remains evidence, not a next action.
Recovery and `connection.test` share cause-specific transport hints. Turn work
items in status and retained status observation add optional, bounded `message`
and `hint` fields, and `reason` also recognizes saved reason-only records.
