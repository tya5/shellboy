# 状態境界と実装・代表回帰の対応

採用: W3/SP2の[規範表](control.md#状態境界の規範表)を、各domainの既存保存・再起動境界へ対応させる。表の状態を新しいメモリ状態機械・DSLへ移さない。下表の回帰名は実行可能な既存fixtureを指し、全組合せの網羅や全OSでの成功を意味しない。実行結果と未実施は共有レビュー台帳・標準チェック・各受入記録で区別する。

同じ終端への再保存、遅着/世代不一致、操作対象不在、現在の競合、未知状態、真のDB保存障害は別に扱う。R1-2の前状態表と0件分類の回帰を、通常完了・中断・再起動の違いを消すための万能終端関数に置き換えない。

## 許可状態と現行の発生契機

公開状態型のRun `live→failed` は許可された終端を含むが、現在の製品経路にはRun/Turnを新たにfailedへ書くproducerがない。通常の準備/通信失敗はTurnのrecovery_waitとRun live、attemptのfailed/incompleteを区別して保存し、正本保存障害はControl全体の受付停止と所有資源の停止へ進める。ここへ新しい致命判定やRun failedへの自動変換を追加すると、既存の明示復旧・副作用不確実性の扱いを変えるため採らない。

既存のRun/Turn failed値は未知状態とはせず、終端として表示・照会し、遅い正常完了や失敗で上書きしない。state/完了CAS回帰とactivity優先順位回帰がこの保持を確認する。特にlive Runの汎用「継続中」fallbackで保存済みTurn failed/stoppedを隠さず、前のinflight attemptによる活動表示も復活させない。将来、既存復旧へ戻せないが保存可能なdomain固有の失敗を定義する場合に限り、発生契機・前状態・保存理由・所有回収・通知を定義してproducer/回帰を同時追加する。未定義のproducerを対応表だけで実装済みと見なさない。

## UI対応と再起動の境界

Changedはcommit後の再読のきっかけで、[activity projection](../../src/frontend/activity.rs)が保存済みRun/Turn/attempt/所有処理を一つのDB読取で投影する。`activity_uses_recorded_run_turn_attempt_priority_and_remains_read_only` と `activity_delivery_rejects_a_previous_thread_after_a_slow_database_read`（[frontend_activity](../../tests/frontend_activity.rs)）が状態優先順位・世代を照合する。背景化Noticeは保存結果の要約であり、stopping/stopped/復旧待ちの保存事実の代わりにはしない。

通常終了のsnapshotは取消し前の観測、OS終了codeや副作用完了の推定ではない。再起動も古いPIDを停止せず、旧workを結果未確認として保存する。UIの個別文言・レイアウト・全画面反応の受入と、この状態/保存/通知境界の照合は別のレビュー項目で追う。

## SP8とW7の照合

SP8の独自提案は全体revisionをThread単位へ単純置換する案であり、不採用を維持する。fork/source/ReadPinはThreadを横断するため、既存global revisionを残し、開始時horizon固定と破壊transaction内の現在root/逆出典再評価で進捗と保護を両立する。W7の実装 `19e3e03` / `01cec29`、10k/100kの書込み継続測定（非同梱の検証記録）、上表GC回帰が対応する。SP8を理由に別のcounter/schema/workerを追加しない。独立node中心の制御測定を、巨大出典DAGの最悪transaction時間や実UI性能の証明とはしない。
