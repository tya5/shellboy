# Thread artifacts

An artifact is a Thread-owned record with an independent ID and Core-authored UTC creation and update timestamps. Its versions append from 1, carrying an opaque URI, title, optional MIME and UTC creation timestamp. URI and title require 1 to 2,048 and 1 to 256 UTF-8 bytes respectively; MIME is optional and at most 128 bytes. The owner rejects oversized strings and never normalizes them. Omitted update title keeps the prior title; omitted MIME saves no MIME for the new version.

The existing owner database writer owns both tables and commits them with the mutation receipt. The existing Thread change hint wakes `events.wait` clients, which reread on a matching hint or resync. There is no artifact-specific publisher, queue or worker.

`artifact.list` seeks by immutable artifact ID within one Thread and returns the latest metadata per item. `artifact.get` returns one version when selected, or the latest metadata and a descending page of version numbers and timestamps. Both paged reads allow 1 to 32 rows; cursors bind to the query kind and owning ID. Pages are live reads, not snapshots: refresh from page one to see inserts that sort before the current cursor.

Archive keeps artifacts. Fork and the rewind child copy the complete metadata snapshot with distinct artifact IDs in the existing Thread copy transaction; rewind does not change the original's inventory. Confirmed Thread deletion removes roots in the existing tombstone transaction, with versions removed by foreign-key cascade; canonical `thread.delete_preview` counts all roots in the selected Threads. The finite UI observation reads at most 1,025 indexed roots to report an exact count through 1,024 or an incomplete observation with a lower bound of 1,024. This does not limit artifact registration. Neither deletion nor `artifact.remove` touches referenced content. Core does not interpret schemes or MIME, resolve paths, check existence, fetch, copy, preview or clean up content.
