# List and observation contract (proposal for approval, #408)

## Non-goals

No capability removal: keep current selectors, scopes, ordering, bodies, export fidelity, diagnostics and retention semantics. No compatibility aliases for approved pre-1.0 renames. No new RPC mechanism, shared cursor codec, snapshot store, index, scan, exact-count query, hash service or automatic fetch. This is design only, based on published Core `339e5987bd5adea10fa18c7db4ebf65e089ed3f2` (protocol 27); all file:line references are to that revision. No runtime measurements. Mutations, subscription semantics and provider behavior are not being redesigned.

## Page and observation fields

1. **Page size.** For ordinary resumable record lists, request `limit`, maximum returned `items` (default 50, integer 1..=200; reject invalid explicit values), following `src/protocol.rs:21`. The effective default is min(50, the existing route ceiling); do not raise a smaller safety ceiling. `limit` is neither a byte limit nor a promise to return that many. Body reads use `limit_bytes`; ranked search, fixed reports and grouped statistics retain their own units and limits.
2. **Cursor.** Send an opaque `cursor` from the same command's `next_cursor` with the same effective target, filters, sort and projection. Stay on the same owner (or immutable local corpus for docs). A cursor marks an exclusive boundary, after the last examined candidate when filtering requires it and the implementation supports that boundary. Keep the route's existing invalidation and error codes; on expiry restart without a cursor, not with an invented position. No guarantee of a frozen dataset: `thread list --order created` is live (`src/cli.rs:720`); history binds a watermark/revision (`src/history/list.rs:80`); the existing token can bind encoding (`src/protocol.rs:1799`). No new owner identity in token formats that do not already encode it. Use unchanged page size on continuation as client guidance; do not make it a new cursor validation requirement.
3. **Normalized filters echo.** For owner record pages, return `filters` with effective scope, selectors, ordering mode and bounded projection options from the arguments already used by the reader, including resolved caller defaults. Normalize only where selection already does (e.g. sorted/deduplicated status states and UTC instants, `src/status.rs:330`); never case-fold a literal query or canonicalize a path differently from its lookup. Put the effective page `limit` beside `filters`, not inside it. No input cursor, credential, raw payload or new echo of caller-supplied free-form text (including path/string searches); where a new echo skips such an active filter use `filters.<field>_omitted: true`. That marker describes the echo, not a dropped selector. Compare a filter echo only as a description, not a serialized cache key.
4. **Fingerprint.** Only the existing status snapshot has one. It compares the normalized selection, effective limit and ordered durable, already shareable page facts, before live enrichment (`src/status.rs:755`). Keep the existing digest mechanism. For each ordered item, include `kind`, `id`, `state`, typed ID links, `expect_reply`, saved lifecycle timestamps, and the ordered response-node references and their truncation marker. Use only the saved fields in that allowlist; do not serialize the entire `WorkItem`. The hash projection excludes raw command/body text, credentials or tokens, opaque cursors, unsafe diagnostic prose, observation time, elapsed time, latest live output/stdin observations, transport counters, and out-of-page aggregates. Remove an unsafe field from digest input, not from an authorized response. The existing normalized selection digest stays separate from the echoed fields. Equal fingerprints do not prove identical live replies, complete collection coverage, or continued liveness. Compare like pages from the same instance; different pages can agree, and a fingerprint is never a cursor, global revision, write precondition or secret-redaction boundary.
5. **Exactness and coverage.** A reported `x_count` is exact only with `x_count_exact: true`; `false` means the count is a proven lower bound (`N+`), and absence of the pair means unknown/not requested. Emit the pair whenever the reader already computed a count; omit it only when no count was computed. Never normalize a placeholder zero to a known count or drop a computed count because an older response omitted the flag. `x_omitted` means a projection did not obtain or emit the content, not that it is empty or deleted; `x_truncated` means returned content or member collection is a partial projection, not that a count is inexact. Preserve independently typed unavailable/deleted states and separate redaction flags. `scanned`, `scan_limit`, and `scan_budget_reached` refer to the existing candidate budget of that operation, not matches or total; report them only where already known without additional work, and do not name a budget hit `exhausted`. A capped report without continuation keeps its own coverage marker. A returned slice of a byte stream is not content loss merely because there is a cursor. Sources: `src/protocol.rs:1953`, `src/protocol.rs:2250`, `src/readback/shell.rs:205`.
6. **Empty page.** `items: []` with `next_cursor` means follow that token for more candidate coverage; the next page may also be empty. End a page walk only when `next_cursor` is absent or null. That ends this walk, not necessarily all live data or all retained data. Do not return an unchanged page token as forward progress. A stream's repeated empty read is different: its position can stay put while the producer is live. Existing empty-page witness: `src/control/db/thread_list.rs:635`.

## Get, list and read

- **`get`**: one exact resource's typed detail/metadata, including its saved state or assignment, not a promise of body bytes. Use after discovery or when an ID is already known. Never select a different resource if the exact one is unavailable. An explicit caller/owner default is allowed for singleton scope.
- **`list`**: discover records through a selected projection, not full payload replay; return `items` and, when resumable, `next_cursor`. Excerpts and aggregate reports retain their existing fields and bounds. Rank/search, anchored windows and mixed-resource status are named for what they do, not disguised as exact `get`.
- **`read`**: retrieve a bounded body or ordered output from one exact resource; preserve content mode, encoding, accounting and provenance. Use the route's body position for more. An immutable saved body eventually has no `next_cursor`; live output returns its current `cursor`, and `output_complete` is separate. E.g. `message get --message M` gives the assignment; the proposed `history read --node M` reads the saved message node. `shell get --execution E` gives execution detail; `shell read --execution E` reads output. Never replace one with the other in a retry.

## Identifier names

Use JSON `<noun>_id` (plural `<noun>_ids`), CLI `--<noun>` (repeat a flag when the command already supports a set): `thread`, `run`, `turn`, `execution`, `message`, `node`, `attempt`, `artifact`, `attachment`, `service`, `schedule`, `operation`. Qualify the role when it matters, e.g. `parent_thread_id`/`--parent-thread`, `since_node_id`/`--since-node`, `expect_node_id`/`--expect-node`, `owed_by_thread_id`/`--owed-by-thread`, `asked_by_thread_id`/`--asked-by-thread`. Keep `--to` for a recipient selector, not a Thread-ID alias. Native resource state is `state`; cross-resource state is named for the resource (history `shell_state`/`--shell-state`). A receipt's lookup `--operation` is not the global request `--operation-id` (`src/cli.rs:27`, `src/cli.rs:1085`). Discriminated mixed records may keep `kind` + `id` alongside typed links; don't infer ID kind from its string or reinterpret a shell's observing request ID as its target execution ID. Names, references, tags, positions, digests and opaque cursors are not resource IDs.

## Intentional exceptions

- Top-k search, anchor windows, whole catalogs and capped reports are not page walks. Grouped usage is exempt from the ordinary record-page shape, not from continuation: follow `next_cursor` while `more` is true, including on empty pages. An exact window total describes selected path length, not matches. Preserving the artifact ceiling, history-search ceiling and reports' existing caps avoids changing work budgets merely for uniform spelling. No paging added to fixed reports.
- `artifact get` is exact artifact metadata with a nested, already pageable version subresource. `usage get` remains one command with mutually exclusive attempt and aggregate modes. `docs get` and `rag get` are corpus/reference readers outside owner RPC. No extra verbs for these exceptions.
- Body cursors and watch/wait positions serve distinct purposes; a live body can have no new bytes but still be readable later. `status` is heterogeneous; its discriminant and `id` coexist with typed references. Do not rename stable on-disk, receipt or export identity to achieve CLI uniformity.
- Ordinary pages do not gain a fingerprint or compute a total. Existing domain-specific omission, redaction, tombstone, privacy and unknown states remain distinct. No inferred scan budget for a reader that does not expose one; boundedness work beyond current mechanisms is outside this proposal.

## Migration order (independently landable)

Numbers below describe **one bump per standalone landing**, not reservations. Starting from the audited 27, they would be 28/29/30 if nothing else lands between them. Each implementation branch inherits main's version number, updates the generated schema definitions and stages its own `docs/design/protocol-versions/next-408.md` with the required heading; assign main + 1 at landing (`docs/development/setup.md:203`). This proposal itself has no bump.
